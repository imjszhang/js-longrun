# Long-term task: <name>

Status: design draft. Filling this template does not submit a ticket, enable a schedule or send a message. Use it as `create --brief`; machine policy belongs in task.json.

## Goal and scope

- What result should accumulate, and who uses it?
- What constitutes useful progress? When should the task stop?
- What inputs and actions are allowed or excluded?
- Which existing user authorization and project rules apply?

## One round

- What question or bounded unit of work does one round address?
- Which local input documents and previous artifacts should it read?
- What output and evidence must it produce?
- What counts as a valid empty result, a failure or a conflict?
- Which registered task type and execution profile support this work?

## Cadence and limits

- After-settlement delay or elapsed-hour fixed interval; which timezone?
- Per-round execution time and output-size limits?
- Weekly run quota and queue timeout?
- How should pauses, missed intervals and repeated failures be handled?

## Review

- Does the chosen type require item decisions?
- Which options and reasons are required?
- How long may review wait? What should happen on expiry?
- Should deferred items be eligible for explicit re-review?

## Results and memory

- Where should verified results appear within this instance?
- What prevents duplicate results or overwriting changed artifacts?
- What facts and decisions belong in next-round memory?
- Which temporary test instructions must never become enduring preferences?

## Acceptance and enablement

- What will plan and offline trial demonstrate?
- Which real execution/channel checks remain untested?
- Is this only design, or has the user authorized enabling the task?
- Record the selected type, definition revision, validation result and authorization basis.
